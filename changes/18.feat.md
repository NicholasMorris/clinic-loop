## Discrete-event simulation engine with deterministic event loop

Implemented a heap-based discrete-event engine for SimClinic that:

- Advances a simulated clock only through scheduled events, never through wall-clock time
- Maintains four named queues (intake, prescriber_review, pharmacy_fulfilment, support_inbox) with per-item enqueue and dequeue timestamps
- Draws service times from configurable per-pool distributions (exponential or normal)
- Reads staffing levels, distribution families, mean service times, and hourly costs from `src/clinicloop/world/config/staffing.toml`
- Requires every configuration key with no code-side defaults; missing values raise `StaffingParameterMissing`
- Exposes exactly three SLA rules (`termination_cutoff`, `damage_report_window`, `dispatch_commitment`) via `sla_rules()` that map to inventory IDs (ps-03, ps-04, po-01)
- Reads SLA threshold values from jurisdiction-specific regime tables (AU populated, NZ/UK placeholder with visible seam)
- Generates deterministic run hashes over the ordered event log, enabling reproducibility testing
- Supports event log replay through deterministic re-execution with identical seeds
- Processes items through queues and out the system, with staffing overrides to test "what-if" scenarios
- Passes all determinism, ordering, and SLA rule tests

Configuration values are explicitly labelled "assumed" starter values that must be measured before deployment.
