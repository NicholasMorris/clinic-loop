## M1-2: Discrete-Event Simulation Engine

Implement a heap-based discrete-event simulation engine for SimClinic that:

- Advances a simulated clock only through scheduled events, never wall-clock time
- Maintains four named queues (intake, prescriber_review, pharmacy_fulfilment, support_inbox) with enqueue/dequeue timestamps per item
- Processes items through worker pools with configurable service-time distributions (exponential, normal)
- Routes items between queues: questionnaires → consults → orders
- Draws service times from per-queue seeded RNGs for deterministic reproducibility
- Supports staffing level overrides to simulate staffing scenarios ("what if we reduced X staff?")
- Returns a RunResult containing ordered ItemRecords, queue depth samples, and a deterministic SHA-256 run hash
- Reads all staffing configuration from `staffing.toml` with no code-side defaults (required keys: assumed, assumption_note, service_time_family, mean_service_minutes, staffing_level, hourly_cost)
- Exposes `sla_rules()` mapping rule IDs to inventory IDs (termination_cutoff→ps-03, damage_report_window→ps-04, dispatch_commitment→po-01)
- Validates regime parameters at run startup; raises `RegimeParameterNotSet` for NZ/UK placeholders
- Tie-breaks simultaneous events deterministically by insertion order

Satisfies checklist IDs C0 (SimClinic clock and queues), G1 (determinism and reproducibility), and G2 (regime seam and AU parameters).
