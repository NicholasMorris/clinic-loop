Implement guard: compliance-rule matching for outbound messages.

- Pure, deterministic `check()` function matching assistant text against ruleset rules (products, euphemisms, doses, conditions, advice).
- Text normalisation chain: HTML entity decode, NFKC, zero-width stripping, Cyrillic/Greek homoglyph folding, lowercase, leet substitution, letter-separator collapse.
- AU ruleset with five rules (AU-G-PRODUCT, AU-G-EUPHEMISM, AU-G-DOSE, AU-G-CONDITION, AU-G-ADVICE), neutral citations, and escalation routing with assumed response times (adverse_event 15, suspected_misuse 60, distress 15, pregnancy 60, clinical_advice 240 minutes).
- GuardVerdict immutable dataclass carrying rule ids, jurisdiction, version and text SHA256.
- OutboundPort.send() as the single transport sink; raises GuardMismatch, GuardBlocked, StaleRuleset.
- Optional LLM second opinion (disabled by default) can only add rule ids, never remove.
- Tests: adversarial corpus (0% violation rate), normalisation variants, purity (no IO, deterministic), thread scope (rules match across joined messages), second opinion, ruleset data validation, outbound port validation, conformance (R1, R5, R7, X4).
- Docs: guard.md covering rule categories, normalisation, check contract, GuardVerdict, OutboundPort, second opinion, escalation routing, honesty paragraph.
